# v14.365：快捷条 Viggle 一键按钮 + 档位补齐（2026-11-10）

## 一、先纠正上一轮的错误结论

上一轮我把「下拉里没有 Viggle 档」判成浏览器缓存，**这是错的**。

真实原因：这个 Pipeline 下拉的**数据源是 `QUICK_DEFS` 里 `render_pipeline` 那条的 `cycle` 数组，不是 `OPTIONS.render_pipeline`**。

- `web\extender.js` 第 6683 行 `{ key: "render_pipeline", ... cycle: [...35 项...], cycleLabels: [...35 项...] }`
- 下拉面板渲染、档位序号、进度条、写回值，全部走 `def.cycle` / `def.cycleLabels`
- `OPTIONS.render_pipeline`（37 项）是另一份表，**不是这个下拉的来源**

所以 v14.360 只补了 `OPTIONS`（35→37）和 `ALIAS_CANON`，**漏了 `QUICK_DEFS` 的 cycle / cycleLabels / cycleAliases**，下拉就一直停在 35 项。

截图里的文案 `Sol-H3 Self-Lift Dual-Pass (Default)` / `DMAD 4-Step` / `HyperFlow Flash 14B (4/6/8-Step)` 正是那 35 项 `cycleLabels`，与 `OPTIONS` 的文案（`(default)` 小写、`DMAD 4-step`）不是一套 —— 这是判断数据源的关键证据，上一轮漏看了。

这就是你反复强调的同步顺序里 **cycle → cycleLabels** 那两步。

### B. 快捷条 Viggle 一键按钮

独立 DOM 按钮，**刻意不进 `QUICK_DEFS`**——因为 `HIDDEN_ROW_KEYS = QUICK_DEFS.map(d => d.key)` 会把 QUICK_DEFS 的每个 key 从参数行隐去，`render_pipeline` 一旦进去就会被藏掉。

点击行为（两态循环）：

- 当前不是 Viggle 档 → 切到**普通档** `Viggle Remake Video Edit (...)`
- 当前是普通档 → 切到**换脸档** `... + FaceSwap (...)`
- 当前是换脸档 → 回到普通档

同时套用该档的常规参数：`steps 6 / euler / simple / denoise 1 / refine off / upscale off / output both / image+audio / one_shot off`，并把每个 clip 的 Context 续链关掉（Viggle 每段由源片对应片段驱动，续链会把上一段生成画面带进来）。

按钮副标题实时显示 `Remake 6-step` / `Remake + FaceSwap`，选中换脸档时按钮更亮。

**不新增任何 widget**，参数位置、`KEYS` 71 项、`DEFAULTS` 71 项、后端 94 段（65+29）、枚举 37 全部未变。

### C. 顺带修掉一个会必崩的越界 bug（既有，不是本次引入）

第 7108-7109 行：

```js
posBar.style.background = on ? shades[idx].stripe : C.border;
```

`shades` 由 `h3QuickTintedShades()` 生成，长度固定 `min(8, tints.length)` = **8**；而 `idx` 是档位序号，最大到 `cycle.length-1`（现在 37）。

**选到第 9 档及以后任一非默认档，这里就取到 `undefined` 并抛 `TypeError`** —— 快捷按钮的 refresh 会中断，表现为"点了没反应/档位不刷新"。这很可能就是历史上高档位按钮失效的隐藏原因之一。

改为 `shades[Math.min(idx, shades.length - 1)]`，与同一函数里其他两处的兜底写法一致。
