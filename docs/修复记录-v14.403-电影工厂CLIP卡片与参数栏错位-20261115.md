### 根因 A：`u4k_engine_params` 无内容却占位约 2926px

`u4k_engine_params` 是后端定义的 `customtext` widget，前端给它建了 DOM element 但高度恒为 0。
ComfyUI 0.45 的 legacy 画布布局在推进 `last_y` 时，仍按约 2926px 给它占位，把紧随其后的 `h3_extender_timeline` 推到 **last_y = 4704**。

也就是说：卡片并不是没生成，而是被放到了参数区下方近 3000px 的空白处，再叠加节点高度不足，视觉上就是"全丢"。

**运行时验证**：把它的 `computeSize` 置为 `[0, -4]` 后，`h3_extender_timeline.last_y` 由 **4704 → 1778**（与最后参数行 1754 只差 24px）。

### 根因 B：`syncDomHeight` 在元素未进 DOM 时就放弃了

`syncDomHeight` 首行条件里 `domWidgetRenderMode()` 在 `element.isConnected === false` 时返回 `"pending"`，且只重试 **12 帧（≈200ms）** 就退出。

而 ComfyUI 0.45 **只在节点进入视口时才把 DOM widget 挂进 `#graph-canvas-container > div.isolate`**。加载工作流时视口通常不在该节点上 → 元素长时间不连接 → 高度校正永远不执行 → 节点停在旧值 8280（< 卡片实际 12129），卡片尾部被画布裁掉。

## 三、改动（`web/extender.js`，两处，均在 node 250 的 `setup` 内）

### 1) 让 `u4k_engine_params` 不占位（约第 7864 行）

```js
// v14.403: u4k_engine_params 是后端 customtext 类型的 DOM widget，
// 它的 element 高度恒为 0，但 ComfyUI 0.45 legacy 布局仍给它按 ~2926px 占位，
// 把后面 h3_extender_timeline(CLIP 卡片 + 全局提示词区) 推到 last_y=4704，
// 卡片因此被挤出节点可视区，表现为"全局提示词和 CLIP 卡片全丢"。
// 收进 _hideNames 后走 computeSize=[0,-4] + draw=()=>{} 兜底，卡片回到参数区正下方。
const _hideNames = new Set(["clips_json", "refs_json", "u4k_engine_params", "h3_extender_timeline"]);
```

### 2) 新增「挂载后校正」监视器（同一处 `try` 块之前）

```js
if (!runtime._h3MountWatch) {
    let _h3MountTries = 0;
    runtime._h3MountWatch = setInterval(() => {
        _h3MountTries += 1;
        const _el = runtime.domWidget && runtime.domWidget.element;
        if (_el && _el.isConnected) {
            clearInterval(runtime._h3MountWatch);
            runtime._h3MountWatch = null;
            try { syncDomHeight(node, runtime, true); } catch (eMount) {}
            return;
        }
        if (_h3MountTries >= 60) {
            clearInterval(runtime._h3MountWatch);
            runtime._h3MountWatch = null;
        }
    }, 500);
}
```

> 500ms × 60 = 最长 30s，元素一连上就自行销毁，不会常驻占资源。
