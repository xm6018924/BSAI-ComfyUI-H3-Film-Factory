# 修复记录 v14.373 — extender.js 语法错误导致整个前端插件从未执行

- 日期：2026-11-10
- 影响范围：`web/extender.js`（唯一改动文件）；`extender.py` 同步把 `clips_json` / `refs_json` 改为单行（`multiline: False`），属防御层，不改类型/位置/序列化

## 一、问题的真身

用户连续三轮反馈「参数区数量变少、全局提示词和分镜 clip 全丢了」，此前均被误判为
「clips_json 渲染成超高 textarea 把后面的行挤出可视区」，于是用 computeSize、`widget.element`
打标记、Vue 网格索引、自旋等网格、全局扫描 `.lg-node-widget` 等手段修补，全部无效。

真因不是布局，是**整个前端插件根本没启动**：

`web/extender.js` 的 `cycleLabels` 数组（`QUICK_DEFS` 里 `render_pipeline` 表项内）存在两处硬伤：

```js
..., "Video Recast (V2V Character Swap)", , "Video Remix (No-LoRA Swap)", "Viggle Remake 6-Step", "Viggle Remake + FaceSwap""HyperFlow Flash 14B (4/6/8-Step)"]
```

1. `, ,` —— 数组空位，`cycleLabels[34]` 变成 `undefined`（长度对、值错）
2. `"...FaceSwap""HyperFlow..."` —— **两个字符串字面量紧邻、缺逗号**

第 2 条直接让整个文件在解析阶段就失败：

```
SyntaxError: Unexpected string
```

浏览器（以及 ComfyUI 的扩展加载器）拿到这个文件后**一行都不执行**，因此：

| 应该发生的 | 实际结果 |
|---|---|
| `app.registerExtension({name:"BSAIMiniMaxH3.Extender"})` | 未注册（624 个扩展里查无此项） |
| `addDOMWidget("h3_extender_timeline", ...)` 创建 CLIP 卡片/全局提示词区 | 从未创建（timeline widget 数 = 0） |
| `onNodeCreated` 里对 `clips_json`/`refs_json`/22 个快捷条参数写 `options.hidden` | 从未执行，70 行参数全露 |
| `setup()` 里的 `console.log("[H3 Extender] ...")` | 一条都没有（所以 Console 左栏看不到 extender.js，曾被误判为"加载正常"） |

即：用户看到的「参数区变少」其实是 70 行原样全露着（当时的判断方向反了），
「全局提示词和所有 clip 全丢了」是**真的丢了**——那些 DOM 卡片从来没有被创建过。

该错误由 v14.365「快捷条加 Viggle 按钮 + cycleLabels 追加 3 条」那次改动引入，
因此 v14.365 之后的所有前端修复（v14.368~v14.372 的隐藏逻辑、档位文案、Viggle 按钮）
**全部处于未生效状态**，用户看到的一直是"老样子"。

## 二、修复

把 `HyperFlow Flash 14B` 放回它在 `cycle` 中对应的位置（索引 34），并补回逗号：

```js
..., "Video Recast (V2V Character Swap)", "HyperFlow Flash 14B (4/6/8-Step)", "Video Remix (No-LoRA Swap)", "Viggle Remake 6-Step", "Viggle Remake + FaceSwap"]
```

修复后 `cycle`（38 项）与 `cycleLabels`（38 项）逐项对齐，`cycleAliases` 旧中文键仍全部命中。

### 校验方式（重要，此前踩过坑）

必须以 **module 模式**校验，script 模式会被文件头的 `import` 语句干扰、漏报本体错误：

```powershell
Copy-Item web\extender.js probe.mjs
node --check probe.mjs      # rc 必须为 0
```

- 修复前：`rc=1`，报 `probe.mjs:6801 SyntaxError: Unexpected string`
- 修复后：`rc=0`

文件保持全 CRLF（9275 个 CRLF / 0 个裸 LF），大小 519,182 B 不变（替换前后等长）。

## 三、真机验证（无头 Chrome + CDP，加载用户 v15 工作流）

`chrome --headless=new --remote-debugging-port=9333`（独立 user-data-dir，不触碰用户浏览器），
`Page.reload({ignoreCache:true})` 后 `app.loadGraphData(<v15 json>)`，实测：

| 项 | 修复前 | 修复后 |
|---|---|---|
| `BSAIMiniMaxH3.Extender` 是否注册 | 无 | **有** |
| `node.__h3Extender` | false | **true** |
| timeline（DOM）widget 数 | 0 | **1** |
| node.widgets 总数 | 70 | **71**（70 后端 + 1 timeline） |
| `getLayoutWidgets()` 行数 | 70 | **47**（隐藏 23 行） |
| `clips_json` 的真实索引 / hidden | 10 / false | 10 / **true** |
| 节点高度 `size` | 2174 | **700**（自动收缩） |
| DOM 卡片元素数 | 0 | **73** |

同时确认这套前端是 **legacy canvas 渲染**（`LiteGraph.VERSION = 0.4`、`node.element === null`、
全文档 `.lg-node-widget` 数量为 0），因此参数行只能通过 `widget.options.hidden = true`
从 `getLayoutWidgets()` 里摘除——这也是插件原本就采用的官方路径，只是此前因语法错误从未跑到。

## 四、对旧工作流的影响

- 后端 `extender.py`：`clips_json`（10982 行）、`refs_json`（11009 行）由 `"multiline": True`
  改为 `False`。**仅渲染层**，INPUT_TYPES 的 65 required + 29 optional = 94 段、70 个 widget、
  38 项枚举、每项先后顺序、`widgets_values` 的 71 项序列化长度**全部未变**，旧工作流不会错位，不会 NaN。
- 第三处 `"multiline": True`（11361 行）属 `forceInput: True`，未触碰。
- 前端只修数组字面量，无 API 变更，无参数位置变更。

## 五、复盘（下次必须遵守）

1. ComfyUI 自定义节点的前端文件如果**完全没有 console 输出**，第一反应必须是「文件没执行」，
   而不是「执行了但逻辑没生效」。
2. 改完 js 一律 `Copy-Item → .mjs → node --check`，rc 必须 0；`.js` 上的 `node --check` 会漏报。
3. 判断插件是否加载，不能看"Console 里没有报错"，要直接查
   `app.extensions.map(e=>e.name)` 里有没有自己的扩展名。
