# 修复记录 v14.360：Viggle Remake 档位恢复 + 参数位置零变化

日期：2026-11-10
构建：`minimax-h3-extender-v14.360-viggle-remake-6step-faceswap-tier`

## 一、现象

「电影工厂」渲染管道下拉里的 `Viggle Remake` / `Video Remix` 两档消失，`Video Recast` 之后的档位全不见。

## 二、根因（三件事叠加）

1. **17:15:26 整代回退**：`extender.py`（987,891 B）与 `web/extender.js`（506,962 B）的 mtime 完全相同，且 viggle 关键字命中数均为 0 —— 两份文件被整体换成了 v14.339。此前写回的 v14.355 全部丢失。
2. **前端白名单比后端少 3 项**：`web/extender.js` 的 `H3LegacyCompat.OPTIONS.render_pipeline` 只有 35 项，缺 `Video Remix`、`Viggle Remake`（以及本次新增的换脸档）。该表用于"值不在白名单 → 回退默认档"，所以即使后端有这一档，载入工作流也会被打回 Sol-H3。
3. **上一轮的换脸开关是 2 个新增 widget**：为了挂换脸开关，v14.355 把布局从 71 项撑到 73 项。旧版 71 项工作流在这种布局下尾部错位（Boolean 落在 timeline 位），正是"旧工作流出错/NaN"的来源。

## 三、修复原则

**不新增、不移动、不删除任何一个既有 widget**。前 71 项参数的位置、类型、顺序与 v14.339 逐项一致。

换脸开关改为**档位化**：不占 widget，直接做成下拉里的一个档。

## 六、用法

| 需求 | 做法 |
|---|---|
| 只出 Viggle 片、不换脸（默认） | 下拉选 `Viggle Remake Video Edit (6-step swap/edit LoRA, FL2VA)` |
| 要逐帧换脸 | 下拉选 `Viggle Remake Video Edit + FaceSwap (...)`，模型固定 128 |
| 提高步数 | 节点 `steps` 改 8 / 10（6 步以外都会自动重采样） |
| 换任务类型（增删改） | 环境变量 `BSAI_H3_VIGGLE_TASK=edit` |

LoRA 仍挂 `viggle_remake_swap_comfyui.safetensors`（`LoraLoaderBypassModelOnly`，strength 1.0）。
