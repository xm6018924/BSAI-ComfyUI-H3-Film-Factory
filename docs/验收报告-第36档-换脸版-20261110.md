# 第 36 档 Viggle Remake 换脸版 —— 验收报告

生成时间：2026-11-10 | 被验对象：`output\bsai_clips\h3_clip_250_{1..5}_*_faceswap.mp4`（2026-11-10 00:37–01:36 一轮）

## 一、结论：不合格

不是"差一点"，是**有一类镜头目前从原理上就没换到**：侧脸、低头、手挡、背影这类帧，逐帧独立检测拿不到脸，`viggle_faceswap.py` 就把原帧原样写回去。全片因此会一帧像参考图、一帧回到原演员，观众一眼能看出来。

已达标的部分很扎实，但身份一致性这一项（也是这个任务唯一的目标）没到交付线。

## 二、实测数据

| 项 | 结果 |

| 总帧数 | 1023 帧（源片 1020 帧，+3 为分段网格补齐） |

| 非脸区域保真 | MAE **1.64/255（0.64%）** —— 背景/动作/口型/服装几乎零改动 |

### 2.2 身份一致性（不合格项）

全片每 2 帧采样共 514 帧，用 insightface `w600k_r50` 提特征比余弦：

| 状态 | 定义 | 占比 |
|---|---|---|
| swapped 成功 | 接近参考图、明显偏离原片 | **71.4%** |
| weak 偏弱 | 换了一点但两头都不像 | **13.4%** |
| no_face 无脸 | 检测不到脸 → 原样保留原脸 | **13.4%** |
| flashback 闪回 | 明确仍是原片那张脸 | **1.8%** |

即 **27.2% 的帧身份没换到位**（no_face + weak + flashback）。

余弦相似度（`1.0` = 同一人，insightface 严格同人阈值约 0.55–0.60）：

| 对比 | 均值 | 说明 |
|---|---|---|
| 源片脸 ~ 参考图 | 0.289 | 基线：完全不是一个人 |
| Viggle 出片（未换脸）~ 参考图 | 0.390 | 采样内没换到 |
| **换脸版 ~ 参考图** | **0.483**（中位 0.497，p25/p75 = 0.447/0.528） | 明显提升，但仍在"像但不敢认"的区间 |
| 换脸版 ~ 源片脸 | 0.269 | 从 0.72 掉到 0.27，说明原身份确实被替换掉了 |

### 2.3 失败集中在哪

按 25 帧一桶统计（S=成功 W=弱 F=闪回 N=无脸）：

| 片段 | 重灾区 | 形态 |
|---|---|---|
| clip4 起始 0–24 帧 | **N16/25** | 开场背身/低头，整段没脸可换 |
| clip5 25–49 帧 | **N19/25** | 大特写侧脸，检测全丢 |
| clip1 50–74 帧 | **W12 + N12** | 快速甩头，脸半遮 |
| clip1 75–99 帧 | W5 | 高动态运镜，对齐漂移 |
| clip2 75–99 帧 | **W12 + N7** | 同上 |

反例（好的地方）：clip2 的 25–49、clip3 的全部、clip4 的 50–99，都是 25/25 全成功。**正脸近景的换脸质量是够的**，问题全部出在姿态和遮挡。

### 2.4 这一轮的实际参数（重要）

日志确认：

- 采样 **steps=6**（不是 8）—— V16 的 8 步这轮没生效
- 换脸 **model=256**（reswapper_256），每段耗时 778 / 805 / 874 / 732 / 364 秒，合计约 46 分钟

也就是说这份出片是"6 步 Viggle + 256 换脸"，8 步版本还没被验证过。

## 三、三个根因

1. **逐帧独立检测，没有跨帧跟踪**。`viggle_faceswap.py` 每一帧单独跑 detector，检测不到就直接跳过。而人转头是连续的，前后帧明明有脸，中段却全靠猜。这是 13.4% no_face 的直接原因，也是最容易补的一项。
2. **inswapper 只认正脸模板**。侧脸喂进去只能得到"半张参考脸糊在原轮廓上"，产出的就是那 13.4% weak —— 比不换还难看，因为它把两种五官糊在一起。
3. **身份上下文太窄**。参考图那张正脸 bbox 是 (160,147)–(405,479)，约 245×331 px，而输出脸在近景时超过 256px，512 输入都不算多。256 模型已经是当前最好的一档，剩下的差距只能靠多视图参考（参考图本来有 5 个视角，但只用了最大那张脸）。

## 四、要达到"彻底像"，建议按这个顺序补

| 优先级 | 动作 | 预计效果 | 代价 |
|---|---|---|---|
| P0 | 给换脸脚本加**跨帧跟踪**：检测失败帧用前后最近成功帧的脸框 + 光流/线性插值位置，继续贴图 | no_face 13.4% → 约 2–3% | 改 `viggle_faceswap.py` 约 60 行，单段多 1–2 分钟 |
| P0 | weak 帧改走"**角度门控**"：yaw > 30° 的帧不做 inswapper（保留原脸并做脸型轻修），避免两脸糊在一起 | weak 13.4% → 约 5%，观感从"糊"变"稳" | 同上，约 20 行 |
| P1 | 参考图改成**5 视角合一**：把参考板里的正脸+侧脸各提一个 embedding，按目标帧 yaw 选最接近的那张做 source | 相似度 0.48 → 0.55+ | 需要重写 source 选择，约 40 行 |
| P1 | 换脸后加 **CodeFormer 精修**（本机已有 `codeformer.onnx` / `codeformer.pth`） | 修掉唇部发黑、边缘接缝 | 每段 +8–12 分钟 |
| P2 | 唇色迁移：从参考图取唇部色相，对换脸后嘴部区域做 LAB 局部替换 | 解决"参考图淡粉唇 / 成片红唇"的违和 | 约 30 行，风险是假 |
| P2 | 重跑 **steps=8** 版对比 | 未知，官方 LoRA 没见过细分 σ 点 | 每段 8 分钟，5 段 40 分钟 |

**我的判断**：先做 P0 两项。这两项加起来不到 100 行，能把"27% 帧没换到"压到"5% 以内"，是从不合格到合格的分界线。P1/P2 属于锦上添花，且 CodeFormer 会把每段拉长到 25 分钟以上，性价比明显低于 P0。
