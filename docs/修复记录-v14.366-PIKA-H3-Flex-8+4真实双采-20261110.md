# v14.366：PIKA H3 Flex 8+4 做成真实双采档（2026-11-10）

## 一、结论

`PIKA H3 Flex 8+4 SelfLift Dual-Pass (Ref2VA face-lock)` 从**僵尸档**（下拉里有、后端不认、选中静默回退默认档）变成**真实档**：

- 后端枚举 37 → **38 项**，该项落在 index **29**，紧跟 6+2 的 28；
- 一采 **8 步**（lcm + Pika 六步轨迹细分 σ），二采 **4 步**（euler + beta + denoise 0.45）+ SelfLift x2.0 渐进放大；

## 二、原来为什么是僵尸档

后端 37 项枚举里只有 `PIKA H3 Flex 6+2 SelfLift Dual-Pass`，没有 8+4。而前端 `QUICK_DEFS.cycle` 里早就有 `PIKA H3 Flex 8+4 ...` 这一项（历史上加过、后端没跟上）。

选中它时，值传进后端 `render_pipeline`，但 `_RENDER_PIPELINE_EN2ZH` 里没有这个英文键 → 拿不到中文内部值 → `_rp_mode` 匹配不上任何分支 → 落到 `else: _rp_handled = False`，**静默按默认档执行**。

## 四、8 步的 σ 为什么这样取（关键设计决策）

Pika H3 Flex 是**把 H3 蒸馏成 6 步**的适配器，官方契约是固定 σ 结 `1000 / 750 / 500 / 250 / 100 / 40 (+0)`。

**8 步没有官方表。** 两条路：

- ❌ 换成 ComfyUI `simple` 等间距（1000/875/750/...）：等于让 6 步蒸馏适配器跑它**没训练过的轨迹**，v14.310 的注释已记录过这类做法会掉画质/稳定性；
- ✅ 对 6 步轨迹做**分段线性插值细分**，首尾钉死、强制严格单调递减：8 步贴着训练过的轨迹走，只是步子更细。

实测插值结果（timestep 空间）：

| 步数 | σ 表 |
|---|---|
| 6 | `1000, 750, 500, 250, 100, 40, 0`（与官方逐值相同） |
| 8 | `1000, 812.5, 625, 437.5, 250, 137.5, 70, 30, 0` |
| 10 | `1000, 850, 700, 550, 400, 250, 160, 88, 52, 24, 0` |
| 4 | `1000, 500, 250, 100, 0`（子集，不引入新 σ） |

全部单调递减、首 1000 末 0。**6 步原样返回这一点已单测确认**，所以 6+2 档行为零变化。

## 五、二采配方

| 参数 | 值 | 理由 |
|---|---|---|
| `refine_enable` | **True** | 6+2 档是 False（二采每步 287s 太慢被关掉），8+4 按档名 `Dual-Pass` 语义恢复 |
| `refine_steps` | 4 | 用户要求 |
| `refine_denoise` | 0.45 | 与 TaoMate / Singularity 双采档一致的精修起点 |
| `refine_upscale_factor` | 2.0 | SelfLift 3D latent 放大器的**训练倍率**；挂错倍率的权重比不挂更糟 |
| `refine_align_to` | 32 | x2.0 后高度落在 1088 而非被吸附 |
| `tile_count` | 16 | x2.0 后整段 tokens 接近 TaoMate 规模，16 块把单块激活压到 ~136k |
| `tile_overlap` | 128 | 接缝融合，与现役双采档同值 |
| `tiled_refine` | True | 空间分块防 OOM |
| `_rp_no_temp_chunk` | True | 时间分块会给每段独立 seed → 接缝闪烁/段内碎花 |
| 一采 `sampler` / `scheduler` | `lcm` / `pika_manual` | Pika 蒸馏契约，强制覆盖 |
| 二采 `sampler` | **`euler`** | 不走 lcm：beta σ 不是 Pika 轨迹，lcm 在那里收益不明 |
| `shift_video/audio` | 12.0 / 3.0 | 与 6+2 一致 |
| `denoise` | 1.0 | 一采全噪 |

3D upscaler 权重优先 `minimax_h3_latent_upscaler_3d_fp16`（本机实机验证过），退任意 `latent_upscaler_3d`，都没有则由 `refine_upscaler_model=""` 走默认路径。

## 七、代价与风险（必须先知道）

- **耗时**：一采 8 步 @960×544 ≈ 8 × 60~70s ≈ 8~9 分钟；二采 4 步 @x2.0 latent ≈ 4 × 287s ≈ **19 分钟**。合计约 **28~30 分钟 / 15s clip**，是 6+2 档（6 步单采、约 6.5 分钟）的 4 倍以上，且这还只是 clip1。
- **显存**：x2.0 + 16 块是照着 TaoMate 8+4 的实机结论配的（16 块单块 ~136k tokens），但 PIKA 的 ref2va 条件路径与 TaoMate 不同，**首次正式跑要盯一下有没有 OOM**。
- **画质未验证**：这次只做到"认得档、参数对、能进采样"，**没有出过一张 8+4 的片**。8 步对 6 步蒸馏适配器是"更细的同轨迹"，理论上细节更稳但不会凭空多出训练中没有的能力；实际是否比 6+2 好，需要你拿真 LoRA 跑一版对比。

若嫌慢，可选折中：`8+2`（一采 8 步、二采 2 步）约 18 分钟；或保持 8+4 但把 `refine_upscale_factor` 降 1.0（不放大，二采只做 4 步细化，约 8 分钟且显存最省）。
