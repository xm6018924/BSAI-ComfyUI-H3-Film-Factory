## 三、离线实证：v14.341 修的是真 bug

构造三链式 clip（S1→T2→S2、S2→T3→S3、S3 单点），用真实解析函数跑两套判定：

| clip | 旧逻辑（对比 `names[i-1]`，上一段**起点**） | 新逻辑（对比上一段**终点**） |
|---|---|---|
| 1 | `prev=None → None` **无任何空间规则** | `kind=空间过渡 site=mid` ✓ |
| 2 | `prev=S1 → 空间过渡`（错位：描述的是 clip1 的换场） | `prev=S2(上段终点) → mid` ✓ |
| 3 | `prev=S2 → 空间过渡`（错位） | `prev=S3 → 同场景延续` ✓ |

规则注入预览：clip1 1161 字、clip2 1189 字，均含"整块盖住镜头"。

**旧逻辑的病根**：链式路线（Sk→S{k+1}）下"本段起点 vs 上段起点"永远不等 → 每段都被判成换场，描述的却是上一段的换场，整体错位一段。段1 走不出自己的空间，段2 在段首补做段1 的换场——实测就是 2.083s 那一帧硬切。

## 四、实跑抓到的致命 bug（离线永远看不到）

### 现象
节点 250 入口立刻报：

```
File "extender.py", line 11895, in extend
_viggle_faceswap_on = (_rp_mode == _VIGGLE_RP_FS_LABEL)
UnboundLocalError: cannot access local variable '_rp_mode' where it is not associated with a value
```

### 根因
v14.360 的 P2（"换脸由档位决定"）被写进了**参数解析区 11895 行**，而 `_rp_mode` 的赋值原文在 **12087 行之后**。函数内后文有赋值 → Python 把 `_rp_mode` 判为局部变量 → 11895 读的是"尚未赋值的局部变量"，**每次调用必崩**。

这意味着 **v14.360 之后的节点一次都跑不起来**——之前的"验证通过"全是离线函数级（`INPUT_TYPES` / 参数结构 / 判定的纯函数），没有任何一次真正执行 `extend`。

### 修复（v14.364）
在 11895 之前补一次同源预解析（与 12087–12089 完全一致的归一口径）：

```python
_rp_mode = str(kwargs.get("render_pipeline", "") or "")
_rp_mode = _RENDER_PIPELINE_EN2ZH.get(_rp_mode, _rp_mode)
_viggle_faceswap_on = (_rp_mode == _VIGGLE_RP_FS_LABEL)
```

12087 处会再赋一次相同的值，无副作用。
