## 0. 一句话结论

**第一轮之所以不合格，主因不是后处理不够聪明，而是换脸模型选错。** 同一帧、同一张参考图下：

| 模型 | 5 帧身份相似度 | 均值 |
|---|---|---|
| **inswapper_128** | 0.881 / 0.851 / 0.783 / 0.847 / 0.847 | **0.842** |
| reswapper_128 | 0.658 / 0.613 / 0.364 / 0.577 / 0.596 | 0.562 |
| reswapper_256（第一轮生产用） | 0.565 / 0.526 / 0.287 / 0.533 / 0.563 | 0.495 |
| inswapper_128.fp16 | 0.159 / 0.147 / 0.009 / 0.079 / 0.214 | 0.122（模型损坏，不可用） |
| hyperswap_1a / 1b / 1c | — | 装载即 `AssertionError`，不可用 |

把模型换成 `inswapper_128` 后，clip5 全段（123 帧，最难的大侧脸段）**身份相似度 0.425 → 0.793（Δ +0.368）**，已经越过"同一个人"的阈值（0.6）。这是本轮最大的收益，也是"脸还是原片那张"的直接答案。

## 1. 第一轮数据的更正

1. **no_face 13.4% 被高估**：第一轮的覆盖率脚本为了提速把 `det_size` 降到 480，导致大量可检出的脸被判无脸。用 640 复测，clip5 的 25–50s 段 **25/25 帧普通检测就能检出**。真实"无脸"集中在 clip4 的 0–1s（背身）与 clip1 的 2–3s（甩头）。本轮所有统计一律 `det_size=640`。
2. **旧脚本的低阈值重试从未生效**：那行 `app.get(img, max_num=0, det_thresh=0.25)` 会抛 `TypeError`（`get()` 没有这个 kwarg），被 `except TypeError` 吞掉后静默退化成普通检测。正确做法是临时改 `app.det_model.det_thresh` 再调 `get()`。此 bug 已在 v2 修掉。

## 2. `tools/viggle_faceswap.py` v2 做了什么（P0–P2 全部落地）

| 项 | 实现 | 默认 | 开关 |
|---|---|---|---|
| P0-a 跨帧跟踪 | 命中帧记 `TrackFace`（中心/面积/速度）；丢帧后沿上一帧 bbox 放大 2.0x 回找；连续丢 ≤6 帧时按 kps 速度外推预测位 | 开 | `--no-track` / `BSAI_H3_FACESWAP_TRACK=0` |
| P0-b 误检闸门 | `accept_candidate()` 三道校验：`det_score≥0.30`、224px 对齐裁片拉普拉斯方差 `≥60`、中心位移 ≤1.6×脸宽且面积比 0.35–2.8 | 开 | `--no-gate` / `_GATE=0` |
| P1-a 多视角参考 | 参考图内所有检出脸建池，脸宽 ≥90px 且 `det_score≥0.5` 才入池；>1 张时按 yaw 最接近者优先 | 开 | `--no-multiref` / `_MULTIREF=0` |
| P1-b CodeFormer 精修 | `codeformer.onnx` 512×512 + 标量 weight=0.8，mask 先 erode 40 再 blur 61，mix 0.45，CPU ~1.4s/帧 | **关** | `--restore` / `_RESTORE=0` |
| P2 唇色迁移 | `landmark_2d_106[52:72]` 凸包（实测 52–71 才是嘴唇外轮廓），取参考唇 LAB=[103,150,134]，只迁移 a/b 通道、L 权重 0.3 | 开 | `--no-lip` / `_LIP=0` |
| 姿态门控 | `gate_alpha(yaw)`：≤30°→1.00、≤50°→0.92、≤65°→0.85、其余 0.75 | 开 | `--legacy` |
| 模型选择 | `--model 128 \| 256`，**默认已改为 128** | 128 | `_MODEL` |

CodeFormer 默认关的原因：`cf_test.png` 的对比显示它把脸拉向"通用美颜脸"，对"像不像参考图"是负作用（身份相似度会掉），只在需要去压缩噪点时手工开。

多视角参考在本素材上自动退化：参考板除主脸（bbox 160,147–405,479）外，另两张是全身立绘的侧脸，脸宽只有 53px / 46px，被 <90px 门槛过滤，`pool=1`，代码路径存在但未触发。

## 4. 剩余限制（不粉饰）

1. **真背身帧无解**：clip4 开头 0–1s 人物完全背对镜头、clip1 的甩头段，检测器拿不到正向人脸，这些帧保持原样。v2 的闸门会主动拒绝"后脑勺被误检成脸"的帧（seg4 头 29 帧全部判 miss，其中 11 帧误检被拒：5 lowscore + 6 blur）——这是正确行为，不是失败。
2. **128 在大特写（脸 >256px）唇部偏暗**：clip5 的 f98 近景可见唇色比参考稍深，未到"发黑"程度。若某段特写非常密，可 `--model 256`，代价是身份相似度掉回 ~0.50。
3. **多视角参考在本素材没生效**（参考板侧脸太窄，见 §2），换一张侧脸更大的参考板才会触发。
4. 换脸是逐帧 2D 贴回，**极端角度（|yaw|>65°）轮廓边缘仍有轻微接缝**，v2 用 α=0.75 混合压住，不保证 100% 无缝。
5. 换脸工序是纯 CPU（本机 onnxruntime 只有 OpenVINO/CPU EP，无 CUDA），**约 3.2 s/帧，42 秒片 ≈ 55 分钟**，这是硬成本。
