# extender.py 后端恢复记录 — v14.339 → v14.355（2026-11-10）

## 背景

插件目录里的 `extender.py` 曾被还原成
`minimax-h3-extender-v14.339-hyperflow-h3-flash-recast-cut-guard`（971,094 B / viggle 命中 0），
v14.348–v14.355 八个补丁全部丢失，后果是：
Viggle Remake 档在运行态没有任何 viggle 代码、前端 73 项 `widgets_values` 被判定为 UNKNOWN
布局而整段回退默认值（megapixels 归 0、render_pipeline 打回 Sol-H3）。

恢复底本 = `extender.py.bak_pre_refcrop_20261109_191656`（1,001,457 B / v14.347，viggle 命中 58），
在其上重做八个补丁，产出 `v14.355`（1,014,190 B / viggle 命中 106）。

### 换脸开关语义（2026-11-10 按用户要求收紧）

- **只由工作流面板决定**。代码里已删除 `BSAI_H3_VIGGLE_FACESWAP` 环境变量强制开关分支
  （全文 0 处残留），面板不勾选时绝不启动换脸子进程。
- 面板默认关闭；两个工作流 `node 250` 的 `viggle_faceswap` 也已统一写回 `False`。
- VIGGLE 档开跑时日志会先打一行 `[H3 Viggle] v14.355 换脸开关: 开 (model=128)` 或
  `关（面板未勾选，出片后不换脸）`，便于当场确认。
- `viggle_faceswap_model` 只接受 `128` / `256`，非法值回落到 `128`。

`BUILD` 改为
`minimax-h3-extender-v14.355-viggle-remake-6step+faceswap-ui+sigma-resample+cond-release`。

## 前端 `web/extender.js` 配套（不做则 73 项工作流会被整段回退默认）

- `KEYS` 71 → 73，`DEFAULTS` 66 → 73 并在尾部补 `false, "128"`，与后端 widget 顺序一一对齐
  （`director_fast_target_mp` → `viggle_faceswap` → `viggle_faceswap_model` → `h3_extender_timeline`）
- `BOOLS` + `viggle_faceswap`；`OPTIONS` + `viggle_faceswap_model: ["128","256"]`
- `detect()` + `n === 73 → "CUR73"`；`mapTo()` 输出 73 位、`CUR73` 分支照抄 `w[62..71]`
- `OPTIONS.render_pipeline` 补两条此前缺失的档位键
  （`Video Remix (no-LoRA character swap + motion transfer)`、`Viggle Remake Video Edit (6-step swap/edit LoRA, FL2VA)`）——
  **这是"载入工作流后 render_pipeline 被打回 Sol-H3"的另一半原因**，白名单里没有就会判成"选项外"回退默认
- `ALIAS_CANON.render_pipeline` 补两条中文别名；`BSAI_BILINGUAL_LABELS` 补两行标签
